SSAO → GTAO upgrade — complete implementation for Godot 4.6-stable
Horizon-based ground-truth AO replacing hemisphere-point sampling. Jimenez et al. 2016, adapted for Godot's GLSL compute pipeline.

Overview
What SSAO vs GTAO actually does differently
Godot 4.6 SSAO (current)
Based on Intel ASSAO. Casts rays as random hemisphere point samples. Checks if each sample is occluded by comparing depth. Result is a per-pixel average of how many samples are blocked. Noise comes from the fact that each pixel uses different random offsets — adjacent pixels get different answers, producing the speckle pattern you see on fabric.
GTAO (what we are implementing)
Sweeps horizon angles along N directions instead of random points. Finds the maximum elevation angle that sees sky along each slice. Integrates analytically using cosine-weighted formula. No random hemisphere sampling → no hemisphere noise. Same number of depth reads, far lower noise, physically correct AO equation.
GTAO is already used by UE5 (their GTAO mode), Unity HDRP (GTAO), and Blender EEVEE Next. A community GTAO implementation for Godot already exists as a proof-of-concept using #ifdef directives in ssao.glsl, toggled alongside the existing SSAO — meaning the approach is known to work in Godot's pipeline.

How the GTAO algorithm works — before you write a line
Step 1 — Pick N directions around the pixel
Instead of random hemisphere points, GTAO picks N evenly-spaced directions φ in the screen plane (typically 2–4). Each direction defines a vertical slice through the hemisphere. The direction is jittered per-pixel using interleaved gradient noise to break up structured patterns without adding white noise.

Step 2 — March along each direction, find horizon angle
For each direction φ, sample the depth buffer at S steps outward from the pixel. At each step, compute the elevation angle of that depth sample relative to the current pixel's surface. Track the maximum angle seen so far in both directions (forward and backward along the slice). This gives θ₁(φ) and θ₂(φ) — the two horizon angles for that slice.

Step 3 — Analytically integrate the slice
The AO contribution of one slice is computed analytically from the horizon angles and the projected surface normal angle (γ). The formula is:

GTAO per-slice integral (Jimenez 2016, Equation 5)
```
// n_angle = projected normal angle in slice plane
// h1, h2  = horizon angles (clamped to hemisphere)
float h1c = max(h1, n_angle - PI/2.0);
float h2c = min(h2, n_angle + PI/2.0);
// Analytic integral: cos(n)*sin(h) - h*cos(n) + sin(n)*cos(h) terms
float ao_slice = -cos(2.0*h1c - n_angle)
               - cos(2.0*h2c - n_angle)
               + 2.0*sin(n_angle)*(sin(h1c)+sin(h2c));
ao_slice *= 0.25; // normalise to [0,1]
```
Step 4 — Average across all directions
Sum the per-slice AO values and divide by N directions. Apply a thickness heuristic — samples behind the surface by more than a screen-space threshold are rejected so thin objects don't cast infinite shadow. Apply falloff based on distance from the pixel so far-away geometry contributes less than near-contact surfaces.

Why this removes grain: There is no random hemisphere sampling. The only randomness is the per-pixel rotation of the direction set, which is a smooth interleaved gradient noise that the blur pass removes completely. The integration is analytic (closed-form math), not Monte Carlo. Adjacent pixels get nearly identical AO because they walk along the same depth field — no per-pixel randomness causing the speckle you see with SSAO.

*Side Effects:*
Systems that WILL be affected:
SSIL (Screen Space Indirect Lighting) — ssil.glsl shares the same depth-mip chain and interleave pipeline as SSAO. SSIL reads the normal buffer and uses the same push_constant layout. If you add GTAO parameters to the push_constant struct in ss_effects.cpp, you must update the SSIL push_constant too or the GPU will read wrong memory. Keep all new params at the END of the struct.
Specular occlusion — the SSAO output buffer feeds scene_forward_clustered.glsl which reads it as a single-channel AO value and multiplies it against the specular term. GTAO produces output in the same [0,1] range via the same buffer, so this path works unchanged. No modification needed.
SSAO debug draw mode — the editor's "Debug → SSAO" view reads the same output buffer. GTAO output will show correctly in this mode automatically. The label in the menu will still say "SSAO" — cosmetic only.
Bent normals — Godot 4.6 computes a bent normal from the SSAO pass for specular occlusion. The existing SSAO bent normal output comes from a separate image binding. GTAO does not compute bent normals in this implementation — specular occlusion falls back to the regular AO value. Full GTAO bent normals require a second output image and ~20 more lines of the integration code.
Mobile / Compatibility renderer — GTAO is wired only to the Forward+ pipeline in ss_effects.cpp. The Compatibility renderer in drivers/gles3/ has its own simple SSAO added in 4.6. That path is untouched.
Systems NOT affected at all
Shadow maps — completely separate pipeline
SDFGI / VoxelGI — reads its own radiance cache, not SSAO buffer
SSR — reads depth + normal buffer, not SSAO output
TAA — runs after SSAO is composited into the colour buffer
Glow / tonemapper — post-process, entirely separate
2D / Canvas renderer — never uses SSAO
The one thing to watch: if you changed the SSIL push_constant layout in a previous edit, verify the struct byte layout matches in both ss_effects.cpp and ssil.glsl. A mismatch causes silently wrong rendering with no GLSL compile error.
